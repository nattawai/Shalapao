รัน `gh pr diff $ARGUMENTS` เพื่อดึง diff ของ PR ที่กำลังเปิดอยู่ แล้วตรวจตามเช็คลิสต์ข้างล่าง

ถ้าคำสั่งล้มเหลวเพราะไม่มี PR เปิดอยู่ ให้บอกสั้น ๆ ว่าไม่มี PR ให้ตรวจ แล้วหยุด
ถ้า diff ยาวมาก ให้ตรวจให้ครบทุกไฟล์ อย่าอ่านแค่ส่วนต้น

ตรวจแล้วอ่าน `docs/ROADMAP.md` และ `docs/BACKLOG.md` ประกอบด้วยเสมอ
เพราะข้อบกพร่องบางอย่างเห็นได้จากการเทียบกับเอกสารเท่านั้น ไม่ใช่จากโค้ด

## เช็คลิสต์

เช็คลิสต์นี้มาจากข้อบกพร่องที่เจอจริงตอนตรวจ PR #40–#46 — 6 จาก 7 ตัวไม่ผ่านรอบแรก
แต่ละข้อมีเหตุการณ์จริงรองรับ ไม่ใช่กฎที่คิดขึ้นลอย ๆ

### 1 · ทุกความสามารถที่โฆษณาไว้ มี test แตะครบไหม

ถ้า endpoint บอกว่าแก้ "ยอด / วัน / กระเป๋า" ได้ ต้องมี test ทั้งสามอย่าง

เจอจริง 3 ครั้ง — ครั้งที่ชัดที่สุดคือ `replaceEntry` รองรับการย้ายกระเป๋า
(`input.pocketId` ต่างจากเดิมได้) แต่ทุก test ส่ง `pocketId` เดิมทั้งหมด
บรรทัดที่กันสิทธิ์ของกระเป๋าใหม่จึงไม่มีใครพิสูจน์ว่าทำงาน

วิธีตรวจ: อ่าน CHANGELOG และ comment ของฟังก์ชันว่าโฆษณาอะไรไว้ แล้วไล่ว่ามี test ครบไหม
โค้ดที่ไม่มี test คือโค้ดที่ไม่มีใครรู้ว่าทำงานจริงไหม

### 2 · test กันข้อมูลรั่วข้ามผู้ใช้ มีไหม และไม่ถูกลบหรือ skip

ผู้ใช้ B ต้องเข้าถึงข้อมูลผู้ใช้ A ไม่ได้ — `CLAUDE.md` §2.3 ห้ามลบ ห้าม skip
D1 ไม่มี row-level security ลืม filter แถวเดียวเท่ากับข้อมูลการเงินคนอื่นหลุด

ตรวจด้วยว่า query ใหม่ทุกตัวกรองผ่าน `pocket_member` ที่ยัง active
(`left_at IS NULL`) และไม่มี SQL ตรงจาก route handler

### 3 · CHANGELOG อยู่ใต้ `[Unreleased]` เท่านั้น

ห้ามแตะหัวข้อเวอร์ชันที่ติด git tag แล้ว — โค้ดที่ tag ชี้ไปไม่มีการเปลี่ยนแปลงนั้น
แต่ CHANGELOG จะบอกว่ามี แล้วคนที่ย้อนไปดูจะไม่รู้ว่าเชื่ออะไรได้

เจอจริง 2 ครั้ง ก่อนจะเขียนกฎนี้ลง `CLAUDE.md`

### 4 · commit message ตามแบบแผน

`type(scope): subject` · รูปคำสั่ง · ตัวพิมพ์เล็ก · ไม่เกิน 72 ตัว · ไม่มีจุดปิดท้าย
ห้ามมี `Co-Authored-By` และห้ามระบุเครดิต AI ทุกรูปแบบ

### 5 · ขัดกับเอกสารที่มีอยู่ไหม

อ่าน `docs/ROADMAP.md` และ `docs/BACKLOG.md` ประกอบ

เจอจริง 1 ครั้ง — `getSummary` ตัดกระเป๋าที่ archive ออกจากยอดรวม
ทั้งที่ ROADMAP เขียนไว้ว่า "rollup รวม archived โดยตั้งใจ"
ผลคือยอดรวมบนหน้าแรกไม่เท่ากับผลรวมของยอดกระเป๋าที่ผู้ใช้เห็นบนจอเดียวกัน

ข้อนี้หาไม่เจอด้วยการรัน test เพราะความขัดแย้งอยู่นอกโค้ด

### 6 · กับดักเฉพาะของ Shalapao

- เงินเป็นจำนวนเต็มสตางค์ ห้ามมี float กับจำนวนเงินทุกกรณี
- `entry.repository` ห้ามมีฟังก์ชันที่แก้ `amount_satang` / `occurred_on` / `pocket_id`
  ของแถวเดิมเลย แม้ในช่วงที่ยังไม่ยืนยันยอด
  แก้ = soft delete แถวเก่า + สร้างแถวใหม่ ใน `db.batch` เดียว
- การแก้ที่ย้ายวันต้องเรียก `assertNotReconciled` สองครั้ง — วันเดิมและวันใหม่
  เพราะการลบของวันเก่าก็ทำให้ยอดที่ยืนยันไปแล้วเปลี่ยน
- ยอดรวมข้ามกระเป๋าห้ามบวก rollup ของทุกใบ
  rollup ของแม่นับยอดลูกอยู่แล้ว บวกตรง ๆ จะนับซ้ำทุกชั้น
- รายการปรับตอนยืนยันยอดเป็น INSERT ดิบที่ได้รับอนุญาตรายเดียว โค้ดที่อื่นห้ามเลียนแบบ
